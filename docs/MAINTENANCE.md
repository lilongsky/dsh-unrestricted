# 独立维护与发布记录

## 稳定入口与身份

本仓库独立维护 `dsh-unrestricted`，当前插件版本为 **0.3.2**，已跟进 upstream **master** / [`fbd8475`](https://github.com/yexi-by/dsh-unrestricted/commit/fbd8475d01c7a705da34b7671b8ae9644770eedc)。功能基线仍为 upstream **v0.2.4** / `7beb2d2546599723f3b2958705d1da3b0bbd5e70`。

- 稳定分支：[lilongsky/dsh-unrestricted · master](https://github.com/lilongsky/dsh-unrestricted/tree/master)。
- 固定源码：[v0.3.2](https://github.com/lilongsky/dsh-unrestricted/tree/v0.3.2)。
- 包名：`dsh-unrestricted`；配置 ID / Settings namespace：`unrestricted`。
- 桌面和 Web 状态通道：`/api/dsh-unrestricted/{status,recheck,preview}`。

版本号由 fork 独立管理，不表示 DSH 宿主版本，也不覆盖 upstream 的发布。已安装旧模块版时更新同名包，继续读取原配置；不通过另装一份改名插件迁移。

## 与上游的关系

上游保留轻量的单份正文与整体开关路线。本 fork 维护十个功能开关、快捷组、所选正文指纹及桌面公共 API 集成，两者范围不同。

[PR #6](https://github.com/yexi-by/dsh-unrestricted/pull/6) 已关闭；本 fork 通过自己的 `master` 和版本 tag 发布。后续更新继续比较上游源码、保留作者修复，再回归本 fork 的模块和桌面行为。原作者署名、MIT 协议与第三方来源说明保持不变。

0.3.0 整合 upstream 0.2.4 的 Minimal 自定义 persona 跟踪与清理、结构化输出指引、同预设并发预览和迟到状态错误处理，并保留本 fork 已有的快照一致性、目标 agent 工具视图和公开 API 路由。作者正文与 upstream 0.2.3 相同；全选正文 hash 不变。

0.3.1 合并上游的 [`e64a442`](https://github.com/yexi-by/dsh-unrestricted/commit/e64a44212739a3ab5c6e1119c8b84b774e6a2b1c)（rc.3 兼容性说明）和 `ab63f68`（macOS 桌面安装示例）。两个提交只修改 README；本 fork 同步三语安装、升级、卸载和非默认应用路径说明，并将三语兼容性说明统一到本轮实际验证的 rc.3。保留同名包更新和空闲窗口流程，运行源码、客户端构建产物、模块正文、SDK 依赖及声明范围均不变。

0.3.2 合并上游 0.2.5 及其后续文档整理（`fbd8475`）。本 fork 同步技术文档简化；上游限定 0.2.2-alpha.2 的宿主范围、删除旧 scope fallback、缩窄 Plan 锚点和移除旧版恢复工具的变更不适用于本 fork 的兼容承诺，因此保留现有实现。十个模块、桌面公开 API、原有宿主范围及作者正文均不变。本轮隔离目标为实际 macOS Desktop 自带的 DSH `0.2.1-rc.5`，不据此宣称已支持 0.2.2-alpha.2。

旧的[上游 0.2.3 比较记录](./upstream-0.2.3-review.md)保留当时的查询与整改过程，其中 PR 状态和最新版本描述只属于该日期。

## 运行中的 DSH

发布 fork、构建 tarball 和隔离验证不需要触碰正在运行的正式 profile。0.3.1 本轮未操作正式 profile；验证记录仅含隔离检查，正式 profile 热更新及临时会话验收按对应提交和包 SHA-256 另行记录。

正式热更新安排在明确的空闲窗口。使用宿主原生会话、turn 和任务状态确认空闲；进程时间、文件 mtime 或昨日快照不能作为本轮任务状态的依据。不承诺在活动 turn 中关闭或重载组件仍可无扰运行。

空闲窗口内的维护步骤：

1. 记录当前 profile、组件状态、包字节和需要保持的配置/会话基线，并备份原包。
2. 使用原生组件开关关闭目标插件，确认旧组件释放后再替换已审阅的同名包；保留 bundle 顺序和用户设置。
3. 开启原生组件，在新建的临时会话中核对状态、四模式预览、重新校验、指纹和配置保持情况；在线模型测试另行定范围。
4. 核对保护基线、记录本次实际进程与包版本；清理测试用临时授权。失败时按备份恢复，单独记录恢复结果。

以上是维护流程，不是本轮已执行记录。0.3.1 的正式安装与热更验收必须另有版本、包 hash、实际状态和作用范围证据。

## 发布约定

- 将上游变更与 fork 保留项分别审阅；保留 Git 历史并更新本 fork 的版本元数据。
- 同步 `package.json`、锁文件根版本、README 三语、[MODULAR.md](../MODULAR.md) 与 [CHANGELOG.md](../CHANGELOG.md)。不因插件版本升级扩大 SDK 依赖范围。
- 从审阅结果构建包，逐文件核对包内容与最终 Git 提交。发布 `master` 和固定 tag，后续运行验收绑定该包与提交。
- 历史验收保留原版本、日期与范围；新版本的待验项不写成通过。
